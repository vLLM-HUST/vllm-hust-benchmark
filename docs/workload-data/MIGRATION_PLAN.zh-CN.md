# Workload 数据底座整合与逐类验证方案

> 历史实施记录，不再作为当前计划或实时状态入口。分类、来源、逐能力迁移、研究侧接通、统一打勾表及后续批次已规整到[40类完整迁移清单](WORKLOAD_PR_REORGANIZATION_PLAN.zh-CN.md)。下文保留当时的服务器、工件与执行安排用于追溯，其中“当前”仅指当时截面，不应直接据此部署或判断完成。

更新日期：2026-10-23。本文替代 2026-10-21 审阅稿的实施安排；逐批实施状态以验证清单和固定提交回执为准。

## 1. 目标与职责

在本仓统一维护 workload
分类、来源目录、原始数据取得说明、文件版本与校验、读取适配、输入与答案隔离、必要的准备及任务执行入口。研究仓从这里消费原始任务和数据，在自己的项目中开展观测、特征提取、规律挖掘和机制实验。

不迁入科研观测、SDK/引擎采集钩子、性能剖析、研究特征计算、模式挖掘、机制干预、论文专用训练划分及研究结果。不是将研究仓整个 Python 包复制过来。现有
benchmark、正式验收配置、排行榜和其他同学的执行器不因本次整合而被替换。

数据组件使用独立发行名 `vllm-hust-workload-data` 和导入名 `vllm_hust_workload_data`，与研究仓的 `llm_serving_workloads`
观测实现隔离，避免同名安装包遮蔽。旧的含观测 `0.5.0` 候选包已作废，不是交付物。组件目录暂为 `workload-preparation/`，根入口为 `workload-data`。

## 2. 数据范围与接入原则

- 以全课题已有 36 个细类为分类起点，而不是个人负责的 14 类，也不以测试大纲九类为上限。36 类不等于已经穷尽所有 workload。
- 保留已有 89 个公开来源候选和 8 份企业资产的登记；镜像、切片、同源版本及同一父任务的多次调用不算独立新数据集。
- 已有可用能力先交，缺失来源按类别补接，不等待所有候选完成。
- 使用发布方原始任务、附件、环境和评分契约；不为适配硬件或模型改题、精选解题材料、伪造事件、补出不存在的输入或用退役合成 family 填空。
- 公开来源也可能 gated 或禁止再分发。发布代码、元数据、取得说明和无载荷回执，不把企业原文、gated 任务、答案、凭据、权重或完整运行数据库放进公开 Git、wheel 或 CI 工件。

企业资产全部保留本地接入：PAIO-CHAT-1000、PAIO-CODE-EVAL-1000、PAIO-JSON-500、PAIO-LONG-PREFILL-5000、PAIO-PREFIX-SHARED-5000、PAIO-REUSE-CONV-5000、PAIO-SEMANTIC-SIMILAR-5000、PAIO-LONGTEXT-4000。其可信边界是企业提供的请求数据，不额外声称均为未加工生产流量。

仅登记、已取得、已适配、已抽样读取、已完整执行、已评分分别记录。历史读取或旧服务器结果不自动升级为本次验证。

## 3. AgentBench、GAIA、tau2 的来源纠正

三者对应类别的主要分析和验证优先使用官方原始任务及合理的公开执行方式，不以 QBI 改造版本为默认来源。QBI 历史资产保留在原研究项目，不删除，不混入原版数据和验证分母。

| 来源       | 本次采用方式                                                                                    | 禁止混用的旧范围                                         |
| ---------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| AgentBench | 固定上游版本、任务类别、原生环境、工具和评分，逐环境验证                                        | 带实验 overlay 的四环境 753 任务队列，不等于上游完整套件 |
| GAIA       | 原始问题和附件；固定公开 Agent 框架、模型与工具；原始答案仅评分侧读取                           | v25 冻结精选证据及受控工具的 GAIA-derived 队列           |
| tau2       | 固定上游版本和具体 domain/split/mode，优先验证正常交互方式；需要的用户模型同样遵守 NPU 资源限制 | Telecom solo114 不替代交互式任务，也不冒充其他 domain    |

GAIA 没有唯一指定的官方 Agent 执行器。可参考公开框架，但必须固定提交、依赖和配置，选择原始 GAIA，不默认使用 annotated
扩展题。搜索、浏览、文件解析及代码执行由具名工具承担。图像/音频任务仅在对应模型或辅助工具可用时执行，记录辅助调用和成本，不把辅助能力称作主模型原生能力。

任务能力范围在执行前登记，不按答对与否筛题；Level 和附件后缀不能直接替代能力判断。缺搜索访问、工具、模态能力或环境时明确列缺口，不改成本地精选材料题。部分能力覆盖必须称为子集，不称完整
GAIA。

## 4. 服务器与模型选择

仅使用用户当前授权实例的 NPU；SSH 入口由用户私下提供，不作为公共文档中的长期连接配置。 2026-10-23 实时检查确认两张 Ascend 910B2、每张 64 GiB HBM，可见设备为
`/dev/davinci3`、`/dev/davinci4`，现有服务为双卡 TP=2。此前实例端口和设备号已失效，
不能照搬旧连接或设备配置。设备编号只属于这次分配，不是包的默认值；部署前须重新核查 实际设备、占用与模型工件，不据此假定其他卡或当前服务可被停止。

优先级如下：

1. 发布方明确推荐、开源可取得且可在当前 NPU 和内存包络内运行的模型。
1. 若发布方仅提供商用 API 示例、没有推荐模型，或推荐模型不能在双卡部署，使用已有且任务能力合适的模型，并说明与参考设置的差异。
1. 根据完整权重、架构支持、工具协议、上下文/输出需求和实测能力选择，不凭参数量或文件夹存在判断可运行。
1. 超出双卡资源或缺模态能力的任务记录为资源/能力缺口，待协调更多卡；不默默换极小模型或改题，不转 CUDA，也不擅自使用收费外部模型 API。

当前 Qwen3.6-27B 目录没有权重分片，不能称可部署。Qwen3.5-27B
已在双卡成功服务；11份完整权重与9份配置/tokenizer文件均匹配发布方固定提交，见[工件记录](validation/qwen35-27b-deployable-artifact-20261022.json)。企业回放使用独立128K/非思考配置，原16K配置及失败记录保留。Qwen3-30B-A3B仅完成16分片结构检查，不称已加载或官方校验通过。环境为vLLM/vLLM-Ascend
0.23.0系列、torch-npu 2.10.0.post4，以各来源回执的实际版本和参数为准。

当前容器有 64 GiB 主存及 8 CPU 配额；`/root` 仅约 2.3 GiB 空闲，不能在那里下载模型、数据或生成编译缓存。使用核查过的独立 `/data`
任务目录，复用共享模型的只读原件，控制每批下载和运行规模，不清理别人的文件。

## 5. 按类别验证并交付

先取得并固定各来源原始资产和执行配置，再为每个来源预先确定 3 个样本/完整任务。交互来源存在多种不同执行协议时，分别覆盖其原生子类，不能拿一个环境的通过代替其他环境。

| 阶段       | 操作                                                       | 通过所能证明的内容                                             |
| ---------- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| 取得与读取 | 来源、许可、版本、SHA、行定位、原始字段、输入/答案隔离     | 该选定资产可取得并读取，不证明模型或完整任务可执行             |
| 安装与消费 | 从安装包读取，研究消费者实际调用，不注入旧源码路径         | 使用链路接通，不证明真实模型执行                               |
| 原生执行   | 当前服务器 NPU 模型，完整工具/环境循环及正常或明确失败终态 | 此任务在具名配置下完整执行，不等于答对或整个数据集完成         |
| 原生评分   | 官方/发布方评分器或明确公开实现，记录协议与原始评分位置    | 得到可解释质量结果；0 分可以是模型任务失败，不是执行器必然损坏 |
| 类别交付   | 文档、依赖、抽样回执、失败清单、复现命令及 PR              | 只覆盖清楚列明的来源、子类与能力范围                           |

每源 3 条是接入抽样，不是全量验证、统计显著性证据或性能结论。固定轨迹回放不能替代闭环任务质量验证；HTTP 200、模型正常生成、Python 单测通过也不能替代完整任务与评分。

批次按实际就绪情况推进：先做现有文本模型和轻量原始数据可验证的类别，再做代码/结构化/长上下文，接着逐环境推进工具/Agent、科学任务，最后补充需要特殊模型和环境的多模态等类别。顺序是资源安排，不删减最终范围。每批必须关联分类
ID、来源 ID、原生子类和实际能力，不以 benchmark 名称等同 workload 类别。

## 6. 失败与证据记录

逐来源进度统一维护在 [数据集逐项验证清单](DATASET_CHECKLIST.zh-CN.md) 和
[机器可读台账](dataset-validation-status.json)。每个来源单独打勾，并分开列示获取、读取适配、服务器完整执行和评分/完整性核验；仅在预选样本验证闭环并有脱敏记录后勾选。一个来源多类复用不重复计数，未覆盖的环境或协议仍须明确标注。

逐任务保留唯一来源、原始 ID、样本选择规则、模型/模板/执行器/工具/环境/评分器身份、服务及客户端配置和终态。原始载荷、日志和答案保留在受控目录；公开回执只保留必要脱敏元数据。

至少区分：`NOT_ACQUIRED`、`NOT_ADAPTED`、`ACCESS_REQUIRED`、`ENVIRONMENT_UNAVAILABLE`、`MODEL_CAPABILITY_UNAVAILABLE`、`RESOURCE_LIMIT`、`HARNESS_ERROR`、`TIMEOUT`、`MODEL_TASK_INCORRECT`、`SCORER_UNAVAILABLE`、`END_TO_END_EXECUTED_AND_SCORED`。执行与质量分别记录，不用一个
PASS 掩盖差异；不能按结果丢弃失败任务或用重试成功覆盖原始尝试。

## 7. CI 与 PR

CI 只做 CPU 正确性 smoke：安装包资源、分类/来源状态、读取映射、输入与答案隔离、临时软件夹具、公共入口和数据-only 边界。不加载模型、不做性能测试、不访问企业/gated
数据，不把软件夹具称真实 workload 证据。

- P0：数据-only 底座、独立命名空间、目录和安全检查。明确尚未服务器验证的来源；不将目录登记当成完整执行。
- 后续按 workload 类别提交来源/执行器接入及服务器抽样验证 PR。每个 PR 列已跑通、模型答错、环境/能力受阻和未跑范围，不等所有类别齐备才让已验证部分可用。
- 配套研究 PR 只修改数据依赖和消费接线。观测、标准化研究特征、D1/D2/D3 分析、机制干预和旧研究证据保持研究仓所有。
- 提交前核对最新主线及相邻 PR，避免重复实现；不自动合并。
