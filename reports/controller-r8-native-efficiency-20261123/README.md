# 请求限流控制器 R8 原生参考效率

11 月 23 日的正式双卡补采覆盖课题四 V2 §4.1 的三项证据。直连与经控制器各三轮原生计时，另有同配置的六轮算量观察， 独立 B1 完整参考分母已核验适用。交接方使用原阶段归档和启动原件在
CPU 上完整复算，并独立回读结果包。 本次发布从固定参考统计重算分母，并用正式交接的两臂汇总复核数值及门槛。复用了已有的硬件记录。

## 工况及结果

两臂共用冻结 R8 E36/R80、Qwen3.5-35B-A3B BF16、TP2 双 Ascend 910B2。 每轮按固定顺序执行 MMLU-Pro 200 题，最大输出 256 token
并保留 EOS。每轮 282,265 输入 token、51,200 输出 token。 两臂各完成 600 个请求，经控制器的 600 个请求均有放行及释放回执。正式计时无详细算量插桩。
从首个正式请求进入模型引擎计起，到整批排空后双 rank 同步结束。计时包含首次准入后的空转，首次准入前的路由和等待由服务指标覆盖。

有效算力下界按 `F_lower / (2 × T_upper × 10¹²)` 计算。两臂共用独立 B1 参考算力上界，每卡 **≤19.3404 TFLOP/s**。 参考的三轮算量上界合计
5,438,638,334,450,385 FLOP，保留依赖图的三轮关键路径下界合计 140.60316791316519 秒。 目标臂耗时不进入参考分母。效率按有效算力下界除以参考算力上界再乘

## 封存交接

在有归档读取权限的环境中，按两份交接回执核验原件。原件、重新封装后的结果和配对证书均有独立摘要。 交接包的 `v2-readback.json` 和
`v2-companion-readback.json` 保存逐轮数据、最终证书及参考门禁。 复算源码固定为 `2b7158a5d7f1ef337bec0babf01f7ed743540cac`，用
`from-checkpoints` 读取原件，再用 `verify_acceptance_package.py` 校验结果包。 完整存档中的 11 份阶段归档及 41,399
个嵌入文件已由交接方回读校验。
