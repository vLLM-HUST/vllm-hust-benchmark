**不确定性（必须与结论一起引用）**：两组验收的含义是“未检测到正确率变化”，不是“已证明变化小于 2 pp”。

|     |   点估计 | 两层 bootstrap 95%（运行、题目） | 运行级 Welch t 95% | 重采样差值 < −2 pp 的占比 |
| --- | -------: | -------------------------------- | ------------------ | ------------------------: |
| TP2 | −0.80 pp | [−3.20, +1.48]                   | [−2.39, +0.79]     |                       15% |
| TP4 | −0.25 pp | [−2.62, +2.00]                   | [−2.17, +1.67]     |                        7% |

最后一列是两层 bootstrap 重采样中正确率差低于 −2 pp 的样本占比，只说明当前数据不能排除这种程度的损失；它不是“真实损失超过 2 pp
的概率”（那需要贝叶斯先验，本报告未做），也不是显著性检验的 p 值。

− 2.0 pp 门限是对点估计的产品容忍幅度，不是非劣效检验：以本轮观测的运行波动，真实 −2 pp 的损失有约一半概率通过， −3 pp 约 13%。要在 95% 置信度下排除 −2 pp
损失，需要更多运行或更大题集。

## 为什么改标准

native 是对照基线而非真值。同配置新起的 native 运行按旧严格门自身就“退化”2–3 题；根因是解码注意力算子
（`npu_fused_infer_attention_score`，TND）和多 prompt prefill 的数值随批组成变化，native 同样受影响，MuxPD 的 P/D
分离只改变了批组成。新标准以标准答案评分（截断计错），用多次运行的总体正确率、截断率、传输失败和 系统性丢失（候选全错且 native
全对）判定，并要求预先声明的性能收益。阈值和方法先冻结再采集（TP2 03:51Z，TP4 04:58Z，sha256 见 `data/*.sha256`），只用 native
自身波动标定。冻结文本见 `data/QUALITY-V2.md`、`data/QUALITY-V2-TP4.md`。

## 性能明细

13 个冻结计划（burst/contend/mixed/short），指标 out_tok_s、goodput_frac、TTFT p50/p99、TPOT p50、ITL p99、最长停顿。
完整逐格数值见 `data/perf-v2-native-vs-default.txt`（TP2）和 `data/perf-v2-tp4-native-vs-default.txt`（TP4）。

- 一致的大幅收益：goodput 比例（如 TP2 mixed-r1.6-s2 0.03→0.66，TP4 mixed-r1.6-s1 0.10→0.91）、最长停顿（约 0.6–0.9 s →
  0.1–0.4 s）、mixed 类 ITL p99（约 0.54 s → 0.08–0.09 s）、过载 short 类输出吞吐（TP2 +7–9%，TP4 +13–16%）和 TTFT。
- 一致的退化：轻负载 contend/mixed-r1.0 的 TTFT p50（+0.1–0.2 s），burst/contend 的 ITL p99（约 3 倍，绝对值仍 < 0.1 s），
  TP2 burst/contend 的 TPOT p50（+5–8%）。
- 规则说明：2 对 3 轮时单格假阳性约 10%（TP2），3 对 3 轮约 5%（TP4）；91 格中预计各有约 9 / 5 个假收益和假退化。 幅度 < 1%
  的吞吐格（burst、contend、mixed-r1.0）不应视为有意义的变化。TP2 native 与候选相隔约 40 小时采集， 采集日与实现混杂；TP4 两臂同日同卡。性能采集使用
  `87c277c`/`9f6bbe4`，与 `b276a4e` 的默认路径计算一致 （仅新增请求级拒绝和可选布局）。

## ROW 缓解（默认关闭）

`decode_attention_layout: "row"` + `max_prefill_requests: 1`（预设
`scripts/serve-qwen35-muxwise-row.sh`）。

- 质量（TP2）：row-q1、row-q2（`b276a4e`）与 rowfix-q1（`9b0641f`，独立复核修复后）均与原生单请求输出逐字一致 200/200；主规则 154
  题正确。旧严格门 PASS（`data/GATE-ROW.md`）。
- 代价（TP2，13 计划 × 2 轮，`data/aggregate_row.json`；**全部测自修复前的 `b276a4e`，不代表当前分支 `9b0641f`
  及之后版本的开销**）：相对默认模式，输出吞吐 burst −6%、mixed-r1.0 −2%~−8%、 contend −27%~−28%、mixed-r1.6 −34%~−39%、short
  −44%~−45%；TPOT p50 为 1.6–3.0 倍；TTFT p50 为 1.2–45 倍 （contend 约 1.2 倍，burst 约 3.2 倍，mixed-r1.6 约
  31–45 倍）。 `9b0641f` 去掉了图填充行的多余主机侧更新，只做了质量复核（rowfix-q1），未重测性能；修复后的开销未测，推测不高于上述数值。
- 适用范围：仅 TP2 已验证；TP4/TP8 未验证。它保证“与单请求一致”，不保证“更正确”。

## 独立复核

- 代码（`data/CODE-REVIEW-20261106.md`）：无阻塞问题；一项 major（图模式填充行被当作真实行，只影响开销）与一项 minor （被拒绝请求未告知数据并行客户端）已在
  `9b0641f` 修复并加回归测试；其余 minor/nit 不在已验证配置内，保留开放。
- 统计（记录在 `data/QUALITY-V2.md` 末节）：用独立代码重算全部端点，数值一致；指出 −2 pp 门限是点估计门限、 case bootstrap 低估运行间方差、S
  的实际零假设应按 1 对 4 理解、TP2 native 采集日混杂、性能规则的多重比较假阳性。 本报告的不确定性表和性能说明采纳了这些意见；冻结门限和判定未修改。
