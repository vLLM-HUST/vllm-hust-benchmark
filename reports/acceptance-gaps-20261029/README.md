## 恢复原件后的性能与成本复算

B0 为 vLLM 0.18 / vLLM-Ascend 0.18（保留原兼容补丁披露）；B1 为纠正后的优化组合，实际基座为 vLLM 0.28.1 / Ascend 0.25.1rc2 开发栈。

采用原同步窗口，包含全部请求及结束同步，保留窗口内计量开销，不混用未插桩最短时间。

| 指标                              |     固定 B0 |         B1 |          改善 |
| --------------------------------- | ----------: | ---------: | ------------: |
| 同步窗口（秒）                    |    238.1267 |   127.5935 |             — |
| 输出吞吐（token/s）               |    215.0116 |   401.2743 |     +86.6291% |
| 等请求权重平均 TTFT（ms）         | 154605.0625 | 86876.8906 | 降低 43.8072% |
| 等请求权重平均 TPOT（ms/token）   |     66.5920 |    33.0916 | 降低 50.3070% |
| 算力租赁估算（元/百万输出 token） |     66.2253 |    35.4849 | 降低 46.4178% |

TTFT 由全部逐请求值复算；两侧各请求均输出 256 token，因此 `(原平均 E2E − 复算平均 TTFT)/255` 等于等请求权重平均 TPOT，并与原客户端聚合核对一致。 流式
chunk 间隔仅用于定位最后输出，不冒充逐 token 时间戳或最终协议结束时刻。

vCPU、256GB 主机内存。[计费说明](https://www.ctyun.cn/document/10029787/10030140)将云盘和公网带宽另计。
本次按用户授权采用类似机器的标价估算，30 天为分析折算假设，不是本机账单或供应商统一月天数规定。

公式：`每卡月价 × 全部保留卡数 × 同步秒数 / (30 × 86400) / 成功输出 token × 1000000`。
当前卡数与请求边界已经核实；仍是类似机器的公开算力租赁估算，而非本机综合账单。

### 利用率与剩余判定

B1 同轮时钟桥将监控对齐到原同步区间，按左侧采样值保持、时间加权得到两卡平均 **22.3946%**。 B0 未保留墙钟与单调时钟的同轮桥，不能借用 B1 的偏移量构造精确 B0 数值。
已核对原控制器 SHA256 与控制顺序：最后一条 starting 采样在客户端启动前，receipt 的 ended 在排空后。 对这两个边界之间所有可能的 238.1267
秒窗口求极值，末尾无采样部分按 0–100% 保守取界，得到两卡平均 **9.4245–16.7177%**。
该范围以墙钟无跳变和左值保持采样模型为条件，支持此模型下的改善方向；不是物理利用率置信区间或精确同区间测量，正式利用率判定仍未闭合。

out8192 的任务分数与本次 out256 服务测量分开保留。现有质量与 SLO 的适用性仍需核对，M06 综合通过状态为 null；不因标量收益为正直接宣称全部验收通过。
