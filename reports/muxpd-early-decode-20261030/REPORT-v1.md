# MuxPD：目标 decode 首个完整 logits 分歧

**目标 MMLU-Pro 07338 的输出位置 1–182，原版与 prefix 候选的完整 logits 全部逐字节相同；位置 183 首次出现数值差异，位置 207 首次出现输出 token
差异。**

主分析与独立原始数组复核一致。这定位的是首次完整 logits 边界差异，不能断言第 183
步才出现内部状态或算子差异。原始答案退化尚未修复；[运行时 Issue23](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/issues/23)保持未完成，[PR27](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/pull/27)仍为
Draft。本轮没有完整答案或性能收益结论。

## 实际结果

| 输出位置 | 自身实际输入相同     | 完整 logits                                                           | 输出 token              |
| -------- | -------------------- | --------------------------------------------------------------------- | ----------------------- |
| 1–182    | 是                   | 数值、规范字节均相同                                                  | 相同                    |
| 183      | 是                   | 248320 项中 197338 项不同；最大绝对差 0.125，RMS 0.023723245538569148 | 两边均为 262            |
| 184–206  | 是                   | 不同；未再次完全相等                                                  | 相同                    |
| 207      | 是                   | 不同                                                                  | native 318，prefix 198  |
| 208      | 否，已有不同输出前缀 | 只作描述，不计算同输入距离                                            | native 2777，prefix 262 |

第 183 步，两边目标均为 row3/8，1340 个 prompt token、182 个已生成 token，实际输入长度 1522、已计算长度 1521、调度一个 token，图描述符同为八行
decode。八条语义记录中，七条的完整输入、前缀及位置相同；只有 seed07151 不同：native 的 seed 前缀长 183，prefix 为 192，总输入长度分别为 1476 和
1485。

这提供了测试调度历史影响的具体依据，没有证明 seed 是原因。相同最终 logits 也不证明所有内部状态都相同。后续将先测试只改变原生支持的
`layers_per_slice: 4 -> 40`，减少 seed 在七条 P 完成前的推进次数；不直接开始另一轮全层观测。

## 采集与对照条件

沿用原 batch7 八题、顺序、先 seed 输出一个 token 再准入七题的流程、seed42、temperature0、原输出上限8192；在目标输出208时停止诊断。它是新进程后验
batch7，不重放原 full200 的前七批历史。

模型 Qwen3.5-35B-A3B BF16、TP4/EP4，物理卡3/4/5/6，逻辑0–3；原 q4、isolated overlap、decode graph 和
FULL_DECODE_ONLY [1,2,4,8]
保持不变。`enable_npugraph_ex=false`、`enable_static_kernel=false`、`HCCL_DETERMINISTIC=true`，batch
invariance 关闭。原源码、数学路径和采样没有改变。

保留普通采集窗口 `[1,200..208]`、128位置校验上限及原80份向量；仅给 rank0 的目标题补充2–199共198份向量。每次采样仅调用一次原 greedy，
旧窗口与新增目标窗口取并集，最多一次原 full-batch clone；普通 bookkeeping 后复用同一次 D2H。实际 greedy 数据为 FP32，八行 clone
最大7,946,240字节；新增目标向量 payload 为196,669,440字节/角色。新文件与普通80文件分开保存。

## 实现与失败保留

原普通向量分析 core、worker helper、plan、engine args 均保留原字节。采集器仅扩展选择条件和独立输出，12个原函数逐字面不变；移除了上一轮状态采集专用
hook，没有新增图内采集、模型重放或 collective。

CPU集成85项通过，独立集中检查28项通过。审查补齐了 prefix 启动前的门槛：必须有 native
新增198份向量、完整208位置、四卡上下文、payload和当前profile全部合格的分析，不能只接受旧80对照的PASS。CPU fixture 初期继承旧状态采集字段而失败，修正的是
fixture，生产侧拒绝旧字段的规则保持不变；原失败日志仍保留在服务器。

此前前四层、40层 MoE
与320份持久状态均相同的结果及采集失败血缘见[前一报告](../muxpd-prefill-state-20261030/REPORT-v1.md)。本轮没有覆盖或重跑这些历史失败。
