本轮在原 batch7 的同一组八题上，只把已有配置 `layers_per_slice: 4` 改为 `40`。07338 的前 208 步完整词表 logits 与 native
全部数值、字节相等；旧 q4 的第 183 步数值分歧和第 207 步 token 分歧均未在该窗口出现。七条 peer 请求的前 208 token 全部与 native 相同，含原先在第 203
步分歧的 07461。

**不能据此宣布答案修复。** 本轮在目标输出 208 截止，没有产生完整答案。原 full200 答案不退化门仍 FAIL，运行时
[PR #27](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/pull/27) 保持 Draft；本轮没有质量、吞吐或 Goodput
的新收益声明。

## 实际改变与调度结果

使用 Qwen3.5-35B-A3B BF16、TP4/EP4、物理卡 3/4/5/6。原八题、顺序、先 seed 产出一个 token 再加入七条 peer、采样参数和 208
截止保持不变；保留外部 prefix 布局处理、隔离重叠、D 图模式
`FULL_DECODE_ONLY [1,2,4,8]`，`enable_npugraph_ex=false`、`enable_static_kernel=false`。原始输入计划和 raw
配置字节不变，通过显式 treatment sidecar 校验唯一 4→40 覆盖。

| ------------------------ | ----: | -------------------------: |
| peer P 推进次数          |    10 |                          1 |
| 每次推进层数             |     4 |                         40 |
| seed 独占 D 次数         |    10 |                          1 |
| 八题同时 D 次数          |   207 |                        207 |
| 各 rank D 图 replay 增量 |   217 |                        208 |
| 截止时 seed 输出数       |   218 |                        209 |
| 截止时每条 peer 输出数   |   208 |                        208 |

q40 的一次 peer P 推进完成 40 层并取得七条完成 ACK；记录 209 次 serving step。replay 采用运行前后计数差，未把启动 capture 次数算作 serving
replay。上述计数不是逐算子图身份验证。

q40 seed 07151 的前 209 token 与旧 q4 的前 209 token 完全相同，仍在第 56 个 token 起不同于 native；旧 q4 额外保留的九个 token
是运行进度差，不能当作共同窗口的内容差异。seed 的完整答案本轮未测，不能将其 token 路径不同称为答错。

## 解释边界与下一步

此前 q4 定位结果是：目标 1–182 logits 一致，第 183 首次观测到数值差异，八行中只有 seed 的实际历史不同。本轮控制 quota
后目标短轨迹恢复一致，为调度节奏影响提供了直接实验依据；尚未证明首个内部状态差异或唯一算子根因。q40 的首次 P 持久状态未重新测量，不能借用 q4 的状态一致结果代替。

本轮仍是后验挑选的 batch7、新进程八题诊断，没有重放原 full200 的前七批历史。下一步保留原 8192 上限、原 scorer 和八题全集，将 q40
跑到全部自然结束或实际长度终止；逐题检查答案、长度及是否延续这次短前缀。有效后才推进匹配对照、运行时代码、原退化题所在批次与全新完整 200 题，不能用局部数值一致代替答案门。
