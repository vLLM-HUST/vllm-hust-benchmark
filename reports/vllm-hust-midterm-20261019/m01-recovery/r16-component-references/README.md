# r16 组件参考与同轮账本

本目录保存 r16 注意力组件的独立数值校验、逐记录图模式计时和同轮语义算量账本。 这些诊断不替代 B0/B1 端到端结果，不构成完整 M01 达标结论。

## 原始证据

`archive.json` 列出压缩归档、分片及每个成员的 SHA256 和字节数。 按索引顺序拼接 `evidence.tar.gz.part*` 可恢复归档；成员路径是原始绝对路径去掉首个
`/`。 解包到独立目录，不覆盖原环境。JSON 摘要保留原始来源路径及哈希，仓库测试将其映射到解包目录核验。

- `fia-reference-r1` 保留首次数值校验失败。原因是 CPU 参考读取了预分配尾部的零值长度。
- `fia-reference-r2` 保存逻辑长度处理修正后的双卡、18 种分支与容量组合的校验。
- `fia-timing-r1` 保存双卡各 2,640 条记录的抽样输出、CPU 参考输出和三组图重放计时。
- 对应 control 目录保存运行、采样、退出和资源释放记录。
- `r16-*` 与词表摘要保存同轮窗口关联、矩阵/GDN 账本和来源哈希。

数值阈值为 `atol=0.005, rtol=0.02`。CPU 参考独立实现分页读取和底右对齐因果注意力。 逐记录计时采用合成 BF16
输入及预热后的同一组缓冲区，不是完全冷启动或真实模型关键路径时间。 计时控制器的 scope 字段沿用旧的数值校验说明；实际范围以归档中的计时计划、探针及逐条原始记录为准。
不修改该原始元数据以消除这一差异。

## 验证

从仓库根目录执行：

```bash
pytest -q tests/test_midterm_r16_components.py
```

测试验证完整归档和来源哈希，保留失败状态，重新核算每卡 5,406,720 个抽样元素的误差、 每条记录的计时中位数、组间波动及同轮窗口账本一致性。
这不等价于全查询行数值校验、全模型质量验证或独立设备指令计数。

完整有效 F、工作负载匹配的整体容量和 M01 达成率仍未判定。
