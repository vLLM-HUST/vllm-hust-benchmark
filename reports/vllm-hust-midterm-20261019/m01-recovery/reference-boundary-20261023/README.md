## 补采方法

同步补采沿用 r10 的 serving 参数，只增加边界 worker 扩展。服务和编译缓存使用新目录， 不导入上一轮缓存；既有只读模型挂载通过 index SHA 和 14 个 shard
的文件状态核对连续性。 这不是重新完成全量权重内容哈希。

客户端保留原 benchmark duration，另记录设备同步包络。包络包含末端 pause、drain 和 RPC 开销，不估算扣除。两个 rank 的身份和指定 MoE 配置在两端核对。 实际
MOD 控制由 Microflow 数值等价性与图回放、KV 策略到引擎 salt admission 的对应关系验证。 重算控制不描述为缓存命中收益；服务全生命周期事件数不冒充测量窗口 FLOPs。

执行前需完成已有任务收尾、四卡独占检查和锁准入。任一步失败停止，不自动重试或换配置。 本目录中的执行计划代表准备完成，不证明设备已运行或验收已通过。
