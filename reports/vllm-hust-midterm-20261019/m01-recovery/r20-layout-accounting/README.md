# r20 实际布局与同轮计数

## 测试对象与方法

Qwen3.5-35B-A3B BF16 TP2，E24/R36、KV recompute、FA Microflow、MTP2、FULL；同一 MMLU-Pro 200
请求、out256、无限到达率诊断负载。新服务和 worker、新输出及可写缓存目录。仅导入固定哈希校验的编译种子，不复用推理状态；不是完全冷编译测试。

模型加载后采集张量 shape、dtype、stride、storage offset、NPU format 及允许记录的配置，不读取权重内容。另采集本轮设备轨迹、HBM 和 HCCS，按请求、末
forward、导出同步三个区间分别对账。

## 结果

- 200 请求完成，0 失败；输入 282265、输出 51200 tokens。诊断吞吐 782.155176 tok/s，不替换正式 B1。
- 两个 rank 各 82 个专家权重张量为连续 BF16 ND，符合已验证数值探针布局。有效配置 weight_nz_mode=1、enable_fused_mc2=0，硬件策略
  CONFIGURABLE。
- 每卡 1750 个 forward、2625 个注意力记录和 875 个 GDN publication；硬件采集退出码 0，无采样错误，四卡资源释放。
- 同轮 10 类语义分项小计 1899940261161121 次基础运算；不是完整有效 F。
- 17 项来源、布局、账本和区间复核测试通过。

## 结论与限制

新增证据确认 r20 加载后实际布局，不追认旧轮次或每次图回放布局。计算量不沿用 r19 计数。请求窗口与尾部、导出同步明确分离；HBM 含估计上下界，HCCS 按两卡 TX 单次累计。

完整有效 F、跨流依赖、完整数值覆盖和匹配的并发容量仍未完成，M01 达成率为空。schema v3 新增布局字段后，旧整字典等值断言失败；修复为保留原 shape/dtype
要求的逐字段校验。失败与修复说明随证据保留，未修改原始记录。

## 证据恢复

完整配置记录 `r20-loaded-configuration.json` 超过单文件发布上限，仅保存在分片归档中，不重复展开。

`archive.json` 列出有序分片、整体压缩流及逐成员大小和 SHA256。逐片验证后拼接，验证整体哈希；解包前拒绝绝对路径、路径穿越、链接、重复成员及覆盖既有文件，再逐文件核验。

根目录 JSON 为归档内同名派生记录的副本。归档保留原始回执与日志、实际导入源码、observer、硬件计数器和 HBM 数据库、恢复脚本及测试
XML。`r20-accounting-build.json` 是修复前生成记录，`r20-accounting-schema-repair.json` 说明随后两处 schema
适配；最终实际脚本哈希由各派生结果记录。
