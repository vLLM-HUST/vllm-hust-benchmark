# 延迟读回整模型补采失败记录

测试对象为 Qwen3.5-35B-A3B，沿用 MMLU-Pro 200 请求、 输出上限 256、无限到达率及 E24/R36、KV recompute、FA Microflow 配置。
观察器使用设备端累计记录和窗口结束后统一读回。

| 尝试 | 结果                                           | 首个已定位错误                                          |
| ---- | ---------------------------------------------- | ------------------------------------------------------- |
| r10  | 104 个成功、96 个失败；未完成设备历史导出      | 状态卸载路径 pinned host memory 分配失败，错误码 207001 |
| r11  | 引擎失败，客户端退出码 -11；未完成设备历史导出 | 同一路径 pinned host memory 分配失败，错误码 207001     |

r11 的失败时刻，容器内存使用量为 137433387008 bytes， 上限为 137438953472 bytes，仅余 5566464 bytes。 该 rank 的 pinned
allocator 已分配 9942664808 bytes， 其中活动分配 9942610216 bytes，缓存差额仅 54592 bytes。 这支持容器内存余量不足的判断，不证明存在固定的驱动
pinned 内存上限。

后续仅对四个已结束实验目录的文件执行 `POSIX_FADV_DONTNEED`， 容器内存观测值降低 18443829248 bytes；4130 个文件保留原 inode、
大小与修改时间。未删除证据、调整服务参数或清理全系统缓存。 内存变化也可能包含其他并发进程的影响。 同代码重试计划与环境回执已保存，计划本身不是成功结果。

两次运行均保留为失败记录，不更新正式 B1，不计入 M01 通过证据。 归档包含原始服务日志、主机观察轨迹、控制器回执、已产出的请求结果、 源码和 SHA256。系统 profiler
数据另行保存，不包含在本归档中。
