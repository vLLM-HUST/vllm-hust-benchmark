# r19 预处理、映射与发布流验证

## 对象与方法

沿用 r19 的 Qwen3.5-35B-A3B、BF16/TP2、MMLU-Pro 200 请求记录。 新增 GDN Q/K L2 归一化与门控的源码语义计数，按实际设备发布的 token
分区计算；特殊函数单列。 利用固定版本 HostMetadata 构造函数在 CPU 重放两 rank 的实际长度和角色，检查分区覆盖及恢复索引。 独立 NPU 资格测试使用固定源码的
acquire/publish/release 方法和真实 pinned-host/NPU 缓冲，测试单缓冲、双缓冲各 129 次 64 KiB 发布。

## 结果

- 请求窗口每 rank 的预处理有效行基础算术为 63061433280 次；按状态更新有效行计算为 62997346080 次。两种范围是替代口径，不能相加。
- 10 类已核算基础算术小计为 1898429231348668 次；TP 分区只求和一次，前缀累加已包含在 GDN H/O 中，Q/K L2 未重复计入 RMS。
- 两 rank 各 876 次发布的 host/device 查询长度一致。每 rank 重放覆盖直接处理 48762 token、映射 prefill 282265 token、映射 verify
  8454 token，包含响应后尾部。
- 258 次 NPU 发布均逐字节匹配。单缓冲实际观察到 20 次上传未完成和 70 次消费未完成；双缓冲未观察到待完成事件，不据此声称覆盖竞争状态。
- 资格测试进程退出码 0，四卡全部释放；运行与可写缓存目录独立，不导入模型状态。20 项本地补充验证通过。

## 结论与限制

预处理语义计数、CPU 映射构造和有界发布流顺序获得补充验证。基础算术小计不等于完整有效 F；指数、SiLU、逆平方根、除法、比较及一元取反未赋予任意 FLOP 权重。 CPU
重放不是对历史设备映射内容的直接观测；NPU 测试不是完整 MTPFrame 初始化、图回放或全模型跨流验证。 仍需闭合实际执行覆盖和匹配形状、精度、状态访问及拓扑的参考容量。M01 达成率保持
null，不替换 B0/B1 性能或质量结果。

## 恢复与证据

先恢复相邻 `r19-direct-logits/archive.json` 的基础归档，再恢复本目录 `supplement.tar.gz`。 本清单固定基础归档哈希，记录 29 个新增成员和 15
个未修改的基础成员引用；两组路径不重叠。 所有成员均有长度与 SHA256；解包时仅接受相对常规文件，拒绝越界路径、重复成员及覆盖已有证据。 新增证据包括三个派生
JSON、真实设备资格测试回执及日志、源码、复算程序和测试记录。
