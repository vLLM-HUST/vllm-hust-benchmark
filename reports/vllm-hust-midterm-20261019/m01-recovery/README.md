# M01 算子计数恢复与硬件内存采样

测试对象：Ascend 910B2，固定学校运行栈，CANN 9.1.0。

2026年10月23日的 [V5.26 方法复核](method-v526-20261023/README.md) 区分有效算力与 同工况可实现效率，核对已有正式计时、MTP 计数和通信参考适用性。
新方法的正式结果尚未闭合；下列原方法证据保留，不作为新口径达标结论。

2026年10月22日的[双worker采集与参考补测](worker-model-20261022/README.md) 已取得两卡完整任务轨迹，并补齐实际通信75种载荷的三次参考。
该补充记录区分本轮已修复项与仍未满足的M01验收条件；下列早期记录保留各自测量范围。

## 轨迹恢复

`recovered-profile-accounting.json` 来自既有 MMLU-Pro 整模型诊断轨迹。 每个 rank 恢复矩阵形状执行算量 1,105,519,340,748,800
FLOP。 计数采用 `TASK` 与 `COMPUTE_TASK_INFO` 关联后的实际执行次数，包含 FULL 图重放； 不以静态算子定义数量代替执行次数。

普通与分组矩阵乘法使用 `2*M*N*K`，分组矩阵输入的 M 已包含各专家路由行数， 不再乘专家数量。该量包含形状填充，尚未扣除无效行，也未覆盖非矩阵算术， 因此不是整模型有效算量。

每个 rank 恢复 110,229 次 BF16 all-reduce、6,335 次 BF16 all-gather 和 2,534 次 INT64 all-gather。通信字节为 API
输入元素数乘数据类型宽度， 不是物理链路收发流量。双 rank 的通信直方图与矩阵算量分别一致。

源数据库路径与 SHA256 保存在 JSON 中。大型源轨迹保留在实验设备； 本目录不包含完整轨迹，重新运行恢复脚本需要源数据库。

## 内存采样校验

`counter-qualification.tar.gz` 包含两个独立探针的脚本、控制回执、数值检查、 设备释放证据，以及 HBM/HCCS 原始采样、数据库和导出数据。
完整逐算子任务轨迹未重复打包。

算子 MemoryAccess 探针的 9 次复制均通过数值检查，计算内核表覆盖其中 6 次 32 MiB/128 MiB 复制；3 次 32 KiB 复制没有对应计算内核行，不计作计数覆盖。

硬件 HBM 探针分别运行约 3 秒的 32 MiB 和 128 MiB 复制。 按当前 CANN 解码器，每个原始 HBM 事件计 32 bytes。 3,504
个采样区间换算与官方导出带宽一致。4 个 HBM 通道的读写采样均覆盖完整测试区间。 128 MiB 复制测得物理读写流量约为逻辑读写量的 98.99%； 32 MiB
复制的物理流量显著低于逻辑量，体现缓存命中，不能用逻辑复制量推定 HBM 流量。

`hbm-sampling-integration.json` 保存每通道采样覆盖率、最大采样间隔、 完全落入测量窗口的字节和所有相交区间的字节，以及按区间重叠比例估算的字节。
按比例估算假定采样间隔内流量均匀；边界区间不做精确流量断言。 设备流量包括同期附带访问，不等于单个算子的独占流量。

## 复算

先在本目录运行 `sha256sum -c SHA256SUMS`，解包归档后根据 `archive-members.json` 核对成员哈希。使用上级目录的
`integrate_hbm_samples.py`，分别传入归档中的 `hbm.db`、探针 `result.json`、 新输出路径及固定 CANN 的 `hbm_model.py`
路径，即可复算采样结果。 脚本同时交叉核验数据库 `HBMbwData`，不覆盖已有输出。

本组证据完成计量方法校验和诊断轨迹的部分恢复，不构成 M01 达成率结论。

## 整模型硬件采样

`model-r1` 为当前 Microflow B1 的应用模式采样，保持同一 MMLU-Pro 200 请求、 282,265 输入 tokens、51,200 输出 tokens，完成
200、失败 0。 逻辑卡 0（物理卡4）的采样结束早于请求窗口，逻辑卡 1（物理卡5）完整覆盖，双卡总流量因此记为空。 该轮不替换既有 B1 性能结果。归档保留完整请求输出、服务与客户端日志、
设备生命周期证据及硬件内存采样；`archive.json` 列出分卷拼接 SHA256 和各成员 SHA256。 按文件名顺序拼接 `hardware-evidence.tar.gz.part*`
后可作为 gzip tar 解包。

`model-r2` 使用独立系统采样，同一配置及输入再次完成 200 请求、失败 0。 两卡各四通道读写采样均覆盖实际请求区间，双卡总物理流量约 65.608 TB。
区间取首请求发出至末响应结束，不包含客户端启动或模型加载。 `recover_model_hardware.py` 通过控制器首末墙钟/单调时钟偏移转换请求时间， 偏移差超过 1
毫秒时拒绝积分；缺任一卡或任一读写通道的完整覆盖时不生成双卡总量。 `summary.json` 保存逐卡边界上下界、按比例估算值及官方解码器交叉核验结果。

两轮均为硬件计量诊断，不参与当前 B1 的吞吐中位数选择。HCCS 原始计数一并保留， 尚未核定时间基准与流量语义，不作为已验证的物理通信流量。当前 B1 的同窗有效算量及匹配参考能力仍需补证。

## SwiGLU 组件补测

`swiglu-reference-r1` 保存 2026-10-20 的双卡 BF16 SwiGLU 组件实测。 形状来自 `device-routing-r9`
的实际专家路由行数和共享专家图容量，共 28 种形状， 每卡对应原轨迹 74,256 次调用。每种形状执行 3 组、每组 100 次图重放， 计时前执行 20 次图预热；输入为固定种子的合成 BF16
张量，不复现整模型工作集。

共享专家调用部署的 `AscendSiluAndMul.forward_oot`，路由专家组件调用 `torch_npu.npu_swiglu`。每种形状抽取最多 9 行、全部 256 个输出通道，
与独立 CPU 方程比较，两卡样本最大绝对误差均为 0。探针、清理退出码均为 0， 采样器无错误，测试前四卡空闲、测试后四卡释放。

## MoE 门控与合并补测

`moe-combine-reference-r2` 保存加权专家合并、共享 sigmoid 门控和输出相加的双卡参考。 14 种图容量对应每卡 37,128 次源调用，形状与调用次数来自
r9；路由和值为固定合成数据。 独立 CPU 方程分别检查加权合并结果与最终输出，两卡抽样最大绝对误差均为 0。 每种形状 3 组、每组 100 次重放，加权中位耗时为
2156.144/2149.857 ms。 该参考不含 all-reduce，不代表原始逐 token 路由或模型工作集。 首轮循环导入失败发生于计时之前，失败原件与设备释放回执一并保存；r2
退出及清理码为 0，四卡释放。

部署源码构造链补全了 SiLU 元数据，标记为源码推导，不改写原始运行清单。 新增 MoE 标量基础运算 549,946,704,384 次，其中包含上一节 SwiGLU 外侧乘法，不能再次重复累加。
同轮部分目录 `same-run-catalog.json` 更新至 1,900,289,589,344,771 次； 特殊函数另列，完整有效算量与 M01 达成率仍为空。
