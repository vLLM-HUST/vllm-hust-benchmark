# Qwen3.5 C16 既有 0.18 数据复用审计

日期：2026-10-22。该目录新增原始证据副本和离线分析，不是新实验，不覆盖原始结果。

## 对象和方法

Native：vLLM 0.18 / vLLM-Ascend 0.18 加 Qwen3.5 text-only 兼容补丁，运行
`dab8ed7c4ee74f2d958dab5528514294`。优化方案：vLLM-HUST，具体组件为 BetterScale resident E16/R20、均衡注意力及 FULL
图等，运行 `fa0e01a32eef456bab4bebe51e4aa7dd`。 两者均为 Qwen3.5-35B-A3B BF16、TP2、C16、900 秒 SWE-prefix-reuse
性能窗口。

```bash
python reports/c16-baseline018-reuse-20261022/audit.py
python reports/frontier-raw-recovery-20261020/verify.py
```

第一条校验本目录归档、两个平台发布的权重清单、对应请求与窗口 token；第二条复核既有 56 个运行归档。 不访问 NPU，不联网，不执行被归档代码。`manifest.json`
记录原始目录、归档和文件哈希。 Native 三个原始结果文件逐字节打包；B1 直接引用已入库的原始恢复归档，不复制第二套。 权重清单是公开平台 API 的字段投影，不是重新读取运行中权重的证明；来源
URL 和采集时间逐份保留。

本地客户端历史 `7446705` 及当前源码均按轨迹顺序分派会话，temperature=0，seed 作为请求参数； 每轮把实际生成 token 回填到下一轮 prompt。该机制可以产生后续
prompt 哈希差异，不能仅用这种差异 或窗口内完成量、平均 prompt 长度不同否定性能比较。尚未确认该源码提交就是两轮运行时加载的客户端， 因此机制说明与逐请求直接证据分开陈述。

原始 Native 服务日志确认 requested FULL_AND_PIECEWISE 最终为 PIECEWISE，MTP2、APC、async 均配置启用。 本目录保存 Native
窗口前、中、后的 npu-smi 原件。其可见物理卡 4/5 为两名 VLLMWorker，2/3 无运行进程；
与某些元数据设备编号不能直接等同，不能把逻辑编号当物理卡号。采样不是连续全主机独占证明。 现有 B1 恢复归档只有配置、摘要和逐请求记录，本目录不声称已经补齐 B1 的设备占用原始采样。

## 采用结论

已有 0.18 数据可保留为指定基线的 SWE-prefix 性能证据。上述 revision、完成请求数和 seed 表面差异
不构成自动重跑理由。两臂运行栈、图模式和驻留策略不同，算术比值由脚本计算，只表示这两个完整部署 记录的描述性比较，不把全部差值归因于一个 MOD，也不替换原有 B1 对 0.25 Native
的配对曲线。

不新增补测窗口；先补核历史客户端与 B1 设备占用的已有证据。此结论不是任务答案质量通过、重复性统计、 M01
有效算力通过或全部中期验收完成。历史插桩窗口的旧方法M01未达标记录和质量缺项继续保留；当前V5.27的M01复算中、未判定，不以旧值作新版判定。
