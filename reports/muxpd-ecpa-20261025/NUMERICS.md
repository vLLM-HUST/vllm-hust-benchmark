# 独立附录：安装包 raw-P 路径的文本重复性

本附录单独保留 2026-10-25 19:51:36–19:59:27 UTC 的重复研究，**不覆盖首轮功能资格的 7/8 文本结果**。 研究完成且 `errors=[]`，但其
`passed` 只表示请求采集及控制器流程完成，不表示数值等价。 未决问题为
[MuxPD Issue #23](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/issues/23)。

输入来自冻结的 `ecpa-numerics-20261025` 目录。[事实提取器](extract_numerical_study.py) 从每条保存响应重新计数、核对 payload
与采样参数，并检查重算结果与控制器汇总一致； [数值事实文件](numerical-study-facts.json)绑定 16 份原件的 SHA256，不打印完整 prompt 或响应正文。
这是一项保存响应的复算，不是独立的原始网络传输审计。

## 构建、请求顺序和观察范围

插件仍为源码 `658b4d0b4e8982bd281499005500ac4c3e0100f5`、wheel `7cc6b1d9…ecd7f`， Manager 仍为源码
`c27d14cd92658e732fa336cb1a453e64f73371cd`、wheel `194e18ce…95e366`。 完整 SHA 及 pinned
Core/Ascend、模型、TP4+EP/BF16 边界见[主报告](README.md)。 本研究没有验证随后修复的 Manager 构建，也与 group-FX 候选无关。

每个端点只启动一次服务，顺序为原生 → 停止原生 → 候选 → 停止候选；两侧共 72 条请求。 每侧先执行 4 轮、每轮 8 个自然语言 prompt，每次最多并发 4 条；随后单独顺序重复 4
次“计算机缓存”解释。 temperature=0、seed=42、max_tokens=96、`enable_thinking=false`，每个 case 跨轮与跨端点 payload 相同。
与首轮候选资格不同，这次候选关闭调度 trace；其他设置由保存的 argv/configuration 和构建记录限定。

并发轮并不是独立冷启动：它们共享该端点的同一次服务历史。实际到达时间、动态组成的模型 batch 和中间状态未固定， 没有跨多次冷启动平衡执行顺序，也没有逐 token IDs、logits 或
logprobs 记录。 四次隔离重复发生在并发轮之后，不能作为新进程初始状态的重复实验。

## 保存响应的重算结果

所有 72 条请求均为 HTTP 200 且输出文本非空。客户端的 `passed` 条件仅检查这两点，**没有语义 oracle**； “完成”或“非空”不能被改写为“答案正确”。

| 配对范围                 | 文本精确一致 | 比较分母 |
| ------------------------ | -----------: | -------: |
| 并发第 0 轮              |            6 |        8 |
| 并发第 1 轮              |            7 |        8 |
| 并发第 2 轮              |            5 |        8 |
| 并发第 3 轮              |            5 |        8 |
| 并发合计                 |           23 |       32 |

| case | 原生不同文本数 | 候选不同文本数 |

四次隔离缓存解释中，原生出现 3 种不同文本，候选出现 2 种。逐条文本摘要、usage、finish reason 和采样设置 保存在数值事实和原始响应中；上述计数没有把不同文本合并为“意思相同”。

## 能够与不能够得出的结论

这些有限观察证明，同一端点在该 BF16 设置和服务历史下也存在文本变化，因此不能用一条原生输出作为无变动的确定性基准。 **原生存在变化并不解释或排除插件引入的差异**，也不证明候选与原生逐
token 等价、语义质量相同或更好。 目前无法将差异归因于数值舍入、状态复用、具体图路径或某一调度决定；没有性能或质量提升结论。

后续归因需要固定 token 输入和实际 batch/到达安排，区分连续服务历史与冷启动，保留首次分歧的 token/logit 证据并做原生自身重复对照。 这属于 Issue #23
的未完成工作，不能由当前功能验收或历史 Goodput 结果替代。
