最新的 [DMA 就绪缓冲区与真实 2P2D 重放](MODEL-RERUN-20261111.md)保存六组、共 1,246 条正式请求。 原四会话负载完整跑通；六会话压力下仍出现 128

## 本快照结论（2026-11-10）

**严重慢尾已在本地缓存路径复现，且可以脱离 PegaFlow、模型和 RDMA 复现。宿主机条件及 CANN 拷贝任务数量是重要影响因素；触发几十秒停顿的底层条件仍在调查。**

本轮完成 178 次带数据标记检查的原生 IPC 恢复，覆盖两台宿主机、四张 NPU，以及注册方式、 内存来源、地址排列、提交分段和 CPU 放置对照。完整模型的对应采集共 15 次请求尝试， 14
次完成，1 次因保存超时失败。启动阶段失败独立保留。

## 本轮实验及排除范围

### 固定缓冲区与控制变量

原生 IPC 探针使用 96 个 NPU 张量平面，每平面 512 块、每块 256KiB；NPU 容量共 12GiB。 CPU 池 5GiB。测量 64 块 / 161 块，即 1.5GiB /
3.773GiB；后者含 15,456 个拷贝描述符。 源缓存先保存一次，之后复用固定源和目标；每次恢复前破坏目标标记，完成后检查两个平面、三个 目标块的标记。计时不含标记检查。

- **注册方式：** V1 MAPPED 与 V2 PINNED|MAPPED 都出现主机差异。真实池注册设备正确。
- **替代主机缓冲：** 通过 MallocHost shadow staging 搬同一数据，结果没有稳定改善；81 上 还增加了 CPU 拷贝开销。独立小缓冲较快不代表替换完整缓存池就能修复。
- **地址排列：** 连续、倒序、固定随机目的块均测量。相同倒序地址重复时也出现大幅变化。
- **有界提交：** 每 512 / 64 描述符同步，没有稳定消除原机器的慢尾。
- **CPU 放置：** 全部 native 线程依次使用全部 CPU、设备本地 NUMA、一个 CPU、两个 CPU， 再重复。没有稳定修复。逐窗口记录中 CPU quota throttling
  增量为零；线程运行队列等待很小。
- **通用 CPU 基线：** 相同 CPU 放置下，整数链、单线程无争用 mutex、CPU memcpy 接近。 它们只能排除通用 CPU 性能的巨大差异，不能证明 CANN 多线程锁没有问题。
- **公开 stream flags：** 独立程序对默认、FAST_SYNC、FAST_LAUNCH、两者组合做交叉对照， 未得到稳定修复。
- **权限差异：** 81 的子进程去掉 CAP_IPC_LOCK 后，小缓冲仍较快；这个阴性结果只覆盖已测 128MiB 申请及拷贝，不能推导更大分配一定不受权限或驱动内存资源影响。

### 软件任务时间与实际搬运时间

独立 pinned 128MiB 拷贝的 msprof 采集中，bulk 被拆为两个 64MiB DMA：原机器每个约 2.56ms， 81 每个约 3.17ms；实际 DMA
时间在这个样本中相近。对应 8 次同步 API 总时间则为原机器 344.8ms、81 54.8ms。采样因此支持调查主机提交、任务回收及完成等待；它没有唯一证明某个
IRQ、锁或固件故障，也不能直接量化完整 95s 恢复中的全部 DMA 时间。

早期 PC/栈采样和运行库反汇编指向任务申请、回收唤醒与重试路径。保留原始地址、映射及反汇编， 避免把去符号库中“最近的导出符号名”当作准确内部函数名。新模型采集使用轻量观察器，原机器仍 在 D2H
保存方向失败，因此慢现象不是只有高频 PC 采样时才出现。

后续 128MiB 顺序对照中，原机器 pinned bulk 也能达到约 7ms；插入事件、检查或创建事件没有 稳定地改变这一速度。不能把一轮较慢结果写成该宿主机永远只有某个带宽。

### 独立任务数量扫描

固定 1GiB、同一源/目标缓冲区，交错执行 H2D / D2H、8 / 64 / 512 / 4,096 / 16,384 描述符， 共三轮；每次调用最多提交 512
个描述符，整次传输后同步。保存所有轮次，包括第一轮。

原机器 MAPPED / 16,384 描述符 H2D 为 8.750、3.780、7.638s；D2H 为 17.619、0.454、4.845s。81 对应各方向约
0.22–0.38s。MallocHost 条件的差距较小。 这给出了脱离上层系统的有限复现器，并显示任务数、内存来源和宿主机条件相互作用。
