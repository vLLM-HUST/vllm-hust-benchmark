# MuxPD 成果补证：TP8 历史争用与 wl38 默认模式性能

提交日期：2026-11-14（北京时间）。对应 [MuxPD #38](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/issues/38)
和
[补证总表 #664](https://github.com/vLLM-HUST/vllm-hust-benchmark/issues/664)。这是既有实测的复核与首次归档，本次没有启动新的设备实验。

## 可引用结论

> 在 Qwen3.5-35B-A3B BF16、TP2 的单轮真实文本派生负载 `wl38/wl-2wiki-r1.6` 上，MuxPD 默认模式的 SLO 达标率由 4.37% 提高到
> 55.90%（+51.53 个百分点），输出吞吐由 161.68 提高到 199.37 token/s（+23.31%）；两臂均 229/229 请求成功。收益伴随 SSE
> 间隔中位数增大，不能外推为质量改善或所有负载的收益。

TP8 **历史 guard 模式**另有独立证据：D 请求最大出词事件间隔 P95 从 385–398 ms 降至 66–68 ms，同时 P 请求 TTFT P95 增加
22.62%–28.49%，吞吐下降 1.96%–3.54%。这是 2026-10-11 的另一版本、协议和配置，不与 wl38 默认模式拼接为同一试验。详细原件、逐轮复算和适用边界见
[TP8.md](TP8.md)。

## TP2 2wiki：身份和计算示例

负载 ID 为 **`wl38/wl-2wiki-r1.6` / seed 38 / pass1**，原始计划 SHA-256 为
`4054d9fc03a41435029e51baf69fc4c9bc26635a5e586c6b038b9deef33076d0`。 名义到达率 1.6 req/s，120 s Poisson
窗口实际生成 229 个请求：45 个 LongBench v1 `2wikimqa` 长请求、184 个 OASST1 validation 续接请求；长请求输入中位数 6257
token。两臂请求 ID、顺序对应的到达时间、kind、输入长度、输出预算及 usage 均与冻结计划一致。到达、混合比例、强制输出长度均为测试设置，**不是生产流量或原生问答评测**。

逐请求定义（单位秒），`events` 为客户端收到**非空 text SSE 事件**的单调时钟时间：

- `TTFT = events[0] - sched`，从计划到达时刻计，包含客户端发送滞后。
- `TPOT = (events[-1] - events[0]) / (completion_tokens - 1)`，输出超过一个 token 时适用。
- `max_gap = max(events[i+1] - events[i])`；不足两个事件时为 0。
- 请求无错误且有非空事件，并同时满足 TTFT ≤1 s（`long` ≤3 s）、TPOT ≤0.1 s、max_gap ≤0.5 s，才计为达标。失败请求计入总分母。
- 达标率 `good / requests`；达标请求速率另列为 `good / span`；输出吞吐为
  `sum(completion_tokens) / span`，`span = last_successful_event - t0`，包含排空阶段，不用名义 120 s 作为分母。
- 百分位使用排序后 `(n-1)*p` 的线性插值。全局 SSE 间隔 p99 是合并所有间隔后的百分位；“每请求最大间隔 P95”先求每请求最大值再取百分位，两者不可混用。

TP2 两臂都输出 29880 token，`span` 分别 184.812266912 s 与 149.873492600 s。因此：

```text
达标率：10/229 = 4.366812% → 128/229 = 55.895197%
差值：(128 - 10)/229 ×100 = +51.528384 个百分点
吞吐：29880/184.812266912 = 161.677580 token/s
   → 29880/149.873492600 = 199.368144 token/s（+23.312177%）
达标请求速率：0.054109 → 0.854054 req/s
TTFT P95：28.262617 → 3.329425 s
每请求最大 SSE 间隔 P95：901.0523 → 277.4754 ms
```

55 个 native 请求、57 个 MuxPD 请求的非空 SSE 事件数与 `completion_tokens` 不同，原因可能包括空文本 token
或合并事件。因此本报告使用“SSE/出词事件间隔”称谓，不将其宣称为引擎内部逐 token 时延。TP2 2wiki 的间隔中位数 **27.11→53.12 ms**，最坏间隔仍 **534.65
ms**，与收益同时保留。

## 质量与适用边界

- 单模型、单节点、TP2/TP4、每配置单轮；没有交替重复、方差或统计显著性证据。固定 MuxPD-first 顺序的时间漂移无法分离。不能推广到 TP8、其他模型、其他并发或生产 SLA。
- 输入来自真实文本；到达、输出长度和比例是派生设置，`ignore_eos=true`，不评估答案。超过 16384 上下文的源行排除而不截断，名单保留于
  [原始 MANIFEST](data/original/wl38/plans/MANIFEST.json)。
- native 使用 chunked prefill，MuxPD 不分块；两者调度器和 worker 不同。这是两种完整配方的比较，不是只改变单个开关的因果消融。
- 模型日志未记录历史模型/tokenizer 文件摘要及固定 revision；[环境说明](ENVIRONMENT.md)明确区分当时运行身份和事后缓存身份，不以当前缓存替代历史证据。
- 原有质量失败不被性能收益覆盖。默认 raw/group 在历史 TP4 同步 QUALITY-V2 协议的系统性丢失仍为 FAIL；ROW 相对 batched native 的旧 FAIL
  也保留。[#23 的关闭](https://github.com/vLLM-HUST/vllm-ascend-MuxPD-hust/issues/23#issuecomment-6703514893)依据重新定义的
  ROW 对 native 单请求一致性：TP4 完整 token 级、TP2 已接受的文本/结束原因级。ROW 默认关闭，性能未测，不能与本报告默认模式收益合并成“质量和性能同时通过”。参考
  [固定质量报告 v4](https://github.com/vLLM-HUST/vllm-hust-benchmark/blob/ce52719c023b766910a198b401ba154369f3945d/reports/muxpd-quality-v2-sync-tp4-20261106/REPORT-v4.md)。

SHA-256，并对 [metrics-v1.json](metrics-v1.json) 作一致性核验。旧汇总在展示前四舍五入，曾造成差值约 0.01
个百分点的舍入差；本报告先用整数计数计算差值、最后显示舍入。

`data/results/**/*.json.gz` 是原始 JSON 的无损压缩，解压即得到本地保留字节；单文件均小于 1 MB，随 Git
归档。[originals-manifest.json](originals-manifest.json)记录每个文件的本地来源、字节数、存储和原始
SHA-256；[SHA256SUMS](SHA256SUMS)绑定本报告发布文件。历史 TP8 大包沿用固定 Release + 原有 SHA，不重复上传。

公开材料包含时序、token 数、来源行号/ID、命令、日志及脚本，不分发源数据、prompt token 数组、生成答案。六份派生请求清单保留每请求 prompt token
数组摘要；重建工作负载需要固定数据源与 tokenizer，详见环境说明。目录及索引只是导航，不代表官方榜单成绩。
