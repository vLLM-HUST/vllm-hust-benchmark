## 同批结果：输出速率与请求速率分开

下表保留 Python 原始浮点序列化值；所有请求级原始时间戳、usage 和流式内容均保存在原件包，不由截图反推。

| 指标 | B0 默认 KV | B1 动态 INT8 |
| --- | ---: | ---: |
| 计划 / 成功 / 请求失败 | 200 / 200 / 0 | 200 / 200 / 0 |
| 正确题数（分母固定 200） | 142 | 145 |
| 输出 token 总数 | 689141 | 705836 |
| 整批墙钟秒 | 669.6414255071431 | 671.2478602509946 |
| 输出 tokens/s | 1029.119426830694 | 1051.52811918994 |
| 完成 requests/s | 0.2986673051902859 | 0.29795253265346056 |
| 平均 TTFT 秒 | 23.64984047065489 | 29.25770500072278 |
| 平均 TPOT 秒 | 0.09621836459523522 | 0.09628791624759424 |
| 达输出上限（保留质量分母） | 21 | 21 |
| 提取答案越界（计错） | 4 | 1 |

输出速率 = 成功请求的 completion_tokens 总数 /（最后完成时间 − 最早提交时间）；请求速率使用相同墙钟分母。输出量增加 2.4225811553803878%，墙钟增加 0.23989476795507336%，完成请求速率下降 0.2393206502365408%，平均 TTFT 增加 23.71206070935752%。因此“输出 tokens/s 观察值增加”不表示同一批题更快完成，也不是单位有效正确答案的吞吐收益。

计时从客户端提交到全部响应收完；不含启动/加载/编译时间。TTFT 取首个非空 content 到达，TPOT =（请求完成 − 首个 content 到达）/（输出 token 数 − 1）。没有独立 reasoning parser，模型生成的思考文本包含在 content 与 completion_tokens 中。所有分位数及连续原始值见 [audited-results.json](audited-results.json)。

## 容量、实际 HBM 与 C8 负结果
