# P2-1 稀疏激活耦合：结果

**一句话**：量化确实把路由翻得很多（W8A8 有 31.5% 的 token×层判决和 BF16 不同，
W4A8 是 49.2%），但**翻转本身几乎不产生误差**——逐 token NLL 损失与"翻了几层"
的相关系数只有 −0.007，各个翻转十分位的 ΔNLL 基本持平。误差量级由权重截断的平滑
漂移决定（P1-2/P1-3 的结论），而不是由离散重路由决定。

## 1. 协议与三臂一致性

| 项 | 值 |
|---|---|
| 拓扑 | TP2 + `--enable-expert-parallel`，卡 1 / 4，端口 8210 |
| 抓取 | `/v1/completions`，提示词以 token id 传入，`max_tokens=1`，`temperature=0`，**客户端串行** |
| 语料 | wikitext-2 298 块（1000 token × 297 + 53），计分 token 296,755 |
| 抓取器 | `--enable-return-routed-experts`，缓冲 `max_tokens=4096, num_layers=40, top_k=8` |

三臂的 PPL 与已发布数字对照（同一批 chunk、teacher forcing）：

| 臂 | 本次 PPL | 已发布 | 差 |
|---|---|---|---|
| BF16 | 7.1700 | 7.1707（TP2） | −0.010% |
| W8A8 | 7.1777 | 7.1750（TP1） | +0.038% |
| W4A8 | 7.3084 | 7.3078（TP1） | +0.008% |

抓取路径是忠实的：三条 PPL 都复现到 0.04% 以内，说明抓路由没有改变前向数值。

## 2. 抓取必须串行（实测出来的坑）

同一服务、同一请求、不做任何模型改动，重复抓两次：

| 客户端并发 | chunk_000 | chunk_001 | chunk_002 | chunk_003 |
|---|---|---|---|---|
| 4 | 100% | 71.25% | 71.18% | 72.44% |
| 1 | 100% | 100% | 100% | 100% |

并发批处理时响应里的 `routed_experts` 行与请求 token 的对应关系会错位。
**所有结果都是 `--concurrency 1` 抓的**；早期 6 并发的 BF16 全量抓取已作废。
串行全量 298 块约 2–3 分钟，代价可以接受。

## 3. 路由一致性

判据：某 token 在某一层的路由 = 该层 top-8 专家**集合**（顺序不计）。

| 指标 | W8A8 vs BF16 | W4A8 vs BF16 |
|---|---|---|
| token×层 集合完全一致 | **68.48%** | **50.75%** |
| top-8 平均重合个数 | 7.633 / 8（95.4%） | 7.389 / 8（92.4%） |
| 40 层全部一致的 token | 0.03%（87 个） | 0.00% |
| 每 token 平均翻转层数 | 12.61 / 40 | 19.70 / 40 |
| 翻转层数中位数 | 12 | 19 |

**层 0 在三个臂里都是 100% 一致**——层 0 的路由输入是 embedding，本来就不该有差异。
这是逐位置对齐正确性的一个独立证据：如果响应行和 token 错位，层 0 不可能全同。

逐层一致率（W8A8 / W4A8）：

| 层 | W8A8 | W4A8 | | 层 | W8A8 | W4A8 |
|---|---|---|---|---|---|---|
| 0 | 100.0% | 100.0% | | 20 | 61.0% | 40.9% |
| 1 | 93.2% | 80.5% | | 24 | 57.2% | **37.6%** |
| 2 | 90.4% | 75.9% | | 28 | **57.0%** | 37.7% |
| 3 | 69.2% | 54.9% | | 32 | 65.8% | 48.0% |
| 8 | 71.2% | 53.2% | | 36 | 65.9% | 45.8% |
| 15 | 66.1% | 47.4% | | 39 | 72.6% | 56.1% |

形状是"前两层几乎不动 → 中段一路降到第 24–28 层的最低点 → 末段部分回升"。
完整表在 `out/routing_coupling.csv`。

## 4. 关键结论：翻转与误差不耦合

按每 token 的翻转层数切十分位（`out/coupling_strength.json`）：

| 十分位 | W8A8 翻转数 | W8A8 ΔNLL | W4A8 翻转数 | W4A8 ΔNLL |
|---|---|---|---|---|
| 1 | 4.7 | +0.00180 | 11.5 | +0.02059 |
| 3 | 8.6 | +0.00171 | 16.1 | +0.02031 |
| 5 | 11.2 | +0.00241 | 18.6 | +0.01990 |
| 7 | 13.9 | −0.00105 | 21.4 | +0.01849 |
| 9 | 18.2 | −0.00039 | 25.1 | +0.01842 |
| 10 | 24.4 | +0.00131 | 29.6 | +0.01592 |

* Spearman(翻转层数, ΔNLL) = **−0.007**（W8A8）/ **−0.008**（W4A8）
* 控制基准 NLL 后的偏相关 = **−0.005** / **−0.006**
* W4A8 的 ΔNLL 从第 1 十分位到第 10 十分位不但没升，反而降了 23%

**读法**：`Spearman(翻转数, nll_base)` = −0.16 / −0.22，说明翻转多的 token 本身
更好预测（路由器在这些 token 上本来就更犹豫）。把 nll_base 控制掉之后，
翻转数与误差的关系在 −0.007 量级，即统计上为零。

原始的分桶口径（按"前一位翻了几层"分 0/1-2/3-5/6-10/11+）在这份数据上没有分辨力：
W8A8 已有 60% 的 token 落在 11+ 桶，W4A8 是 97.7%。那张表仍保留在
`out/routing_buckets.csv`，但结论以上面的十分位与相关系数为准。

### 与预注册判据的关系（必须写明）

README 里预先写死的判据第一条是"完全一致率 ≥99.5% 且分桶 ΔNLL 平坦"。实测一致率
只有 68%/51%，**这条判据的第一分支被击中了**，按字面要判"离散失稳"。

但同一条判据的第二个分支（"翻 ≥3 层的桶 ΔNLL 显著更高"）**明确不成立**，而且
实测的平均重合度高达 95.4%/92.4%（每层只换 0.4–0.6 个专家）。所以问题出在判据
本身：它把"集合完全一致"当成了质量标尺，而在 256 选 8 的硬判决下，8 选集合
只要换掉一个专家就不再"完全一致"，这个指标对任何微小扰动都会剧烈反应。

结论按两个互相独立的证据判：**重合度高 + ΔNLL 与翻转数无关** → 翻转是无害的
排列变化，不是离散失稳。这个判据的事后修正要如实记录，不能假装一开始就想到了。

## 5. 翻转是否集中在权重误差大的专家上

把 `out/expert_flips.csv`（逐 token 集合差得出的换进/换出次数）与 P1-2 的
逐 (层, 专家) 权重误差对齐（`join_p12.py`）：

| 臂 | 样本 | Spearman(翻转次数, w4a8_rel_fro) | Pearson |
|---|---|---|---|
| W4A8 | 9,977 个 (层, 专家) | 0.073 | 0.036 |
| W8A8 | 9,975 个 (层, 专家) | 0.079 | 0.027 |

相关性可以忽略。注意这是一个**低功效**检验：P1-2 已经证明权重误差在专家之间几乎
是平的（没有坏专家），所以这里本来就没有可相关的方差。它的价值只在于排除
"少数坏专家被路由放大"这条解释。

## 6. 结论边界

* 这是**单次前向**的 teacher-forced 提示词路由，不是自回归解码轨迹。解码时一旦
  采样出不同 token，后续位置不可比，所以没有测。
* 语料是 wikitext-2（与 PPL 同源），不是生产流量；只覆盖 40 个主层，MTP 层
  专家在两个产物里都是 FLOAT 且本配置不启用。
* TP2 是为了让 BF16 起得来而强制统一的三臂拓扑，本节数字**不能**与 TP1 的
  性能/精度实验逐位相减（PPL 的一致性只是交叉验证，不是同口径复现）。
* 抓路由会多一次 D2H 拷贝，本服务不用于任何吞吐/时延测量。
* 路由 id 是**集合**口径，top-8 的顺序在 EP 下不保证跨臂一致，未作为判据。
* 没有做 router logits 的 margin 分析（抓取器只给 id），所以"哪些 token 处在
  并列边缘"只能从翻转频次间接推断。

## 7. 复现

```bash
LABEL=bf16 ./run_server.sh   # 然后 capture_routing.py --arm bf16  --concurrency 1（默认）
LABEL=w8a8 ./run_server.sh   #          --arm w8a8
LABEL=w4a8 ./run_server.sh   #          --arm w4a8
python3 compare_routing.py --arms bf16,w8a8,w4a8 --base bf16
python3 analyze_coupling.py
python3 join_p12.py
```
