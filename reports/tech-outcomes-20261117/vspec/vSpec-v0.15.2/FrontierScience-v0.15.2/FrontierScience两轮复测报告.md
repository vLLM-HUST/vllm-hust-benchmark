# FrontierScience：vSpec 0.15.2 两轮复测报告

状态：两轮五臂求解、离线判分，以及一轮独立的逐步 gamma trace 均已完成。本目录为公开证据候选材料，合并状态以 GitHub PR 为准。

## 冻结负载与运行口径

Olympiad 100 题、Research 60 题，固定顺序，共 160/160。求解模型 Qwen3.5-35B-A3B，Ascend 910B2 两卡、TP=2、EP 开启、BF16，最大并发 16、`max_num_batched_tokens=8192`、最大上下文 32768，温度 0、seed 17、每题最多输出 16384 token、关闭 thinking，自动 KV、异步调度、分块预填充、前缀缓存、`FULL_DECODE_ONLY`；无额外客户端预热题。vSpec 候选深度 2/4/6/8，从 8 档起步，`HUST_ISSUE18_VERIFIED_PREFIX_BRIDGE=1`。四个原生臂分别固定 MTP2/4/6/8。第一轮物理卡映射为 2、7，第二轮为 2、5；这是运行环境，不是安装包的卡号绑定。

冻结[题号与顺序](release-candidate/题号.txt)、[运行参数](release-candidate/params/)和[客户端源码](release-candidate/client_source/)均在可公开候选目录。计时为客户端正式求解窗口，吞吐 = 输出 token 数 / 正式秒，**不含服务启动与图捕获**。自然停止使各臂输出 token 总数不同，输出吞吐倍率不是同工作量端到端耗时倍率。

## 动态切换与逐步 trace

首轮 vSpec 从 8 档起步，控制器选择 4/6/8 档分别为 40/16,045/2,174，服务汇总 20 次切档、9 条桥接提交。第二轮分别为 40/15,627/2,316，服务汇总 29 次切档、11 条桥接提交。正式两轮未开启逐步 trace，不能事后还原每次切换时间线。

为补足逐事件证据，另跑一轮同题号的 vSpec 诊断，仅将 `HUST_VSPEC_ADAPTIVE_TRACE=0` 改为 `1`：160/160、零失败，18,167 条调度决策、相邻决策 gamma 的 18 次切换，与服务汇总 18 次一致，另有 9 条桥接提交。切换为 `8→6` 7 次、`6→8` 7 次、`6→4` 2 次、`4→6` 2 次；2 档未使用。诊断轮吞吐 1,212.29 token/s、服务就绪 732.23 秒；trace 影响执行路径，**不参与正式两轮配对**。可公开的[逐步决策](release-candidate/trace/trace-decisions.jsonl)与[切换索引](release-candidate/trace/trace-switches.json)按调度批次记录，不是逐 token 时间戳。
