# HLE-Verified：vSpec 0.15.2 两轮复测报告

状态：两轮五臂求解、离线判分，以及一轮独立的逐步 gamma trace 均已完成。本目录为公开证据候选材料，合并状态以 GitHub PR 为准。

## 冻结负载与运行口径

Gold 文本 64、图像 10；Revision 文本 113、图像 13，共 200/1811 题，按固定比例与确定性系统抽样选择。求解模型 Qwen3.5-35B-A3B，Ascend 910B2 两卡、TP=2、EP 开启、BF16，最大并发 16、`max_num_batched_tokens=8192`、最大上下文 65536、单请求最多一张图，温度 0、seed 17、每题最多输出 16384 token、关闭 thinking，自动 KV、异步调度、分块预填充、前缀缓存、`FULL_DECODE_ONLY`；无额外客户端预热题。vSpec 候选深度 2/4/6/8，从 8 档起步，`HUST_ISSUE18_VERIFIED_PREFIX_BRIDGE=1`。四个原生臂分别固定 MTP2/4/6/8。第一轮物理卡映射为 2、7，第二轮为 2、5；这是运行环境，不是安装包卡号绑定。

冻结[题号与顺序](release-candidate/题号.txt)、[运行参数](release-candidate/params/)和[客户端源码](release-candidate/client_source/)均在可公开候选目录。计时为客户端正式求解窗口，吞吐 = 输出 token 数 / 正式秒，**不含服务启动与图捕获**。自然停止使各臂输出 token 总数不同，输出吞吐倍率不是同工作量端到端耗时倍率。

## 动态切换与逐步 trace

首轮 vSpec 从 8 档起步，控制器选择 4/6/8 档分别为 40/24,770/2,619，服务汇总 24 次切档、12 条桥接提交。第二轮服务汇总 20 次切档、10 条桥接提交。正式两轮未开启逐步 trace，不能事后还原每次切换时间线。

为补足逐事件证据，另跑一轮同题号的 vSpec 诊断，仅将 `HUST_VSPEC_ADAPTIVE_TRACE=0` 改为 `1`：200/200、零失败，26,899 条调度决策、相邻决策 gamma 的 32 次切换，与服务汇总 32 次一致，另有 16 条桥接提交。切换为 `8→6`、`6→8` 各 12 次，`6→4`、`4→6` 各 3 次，`4→2`、`2→4` 各 1 次。诊断轮吞吐 1,414.22 token/s、服务就绪 1,562.63 秒，冷启动仍超过 20 分钟目标；trace 影响执行路径，**不参与正式两轮配对**。可公开的[逐步决策](release-candidate/trace/trace-decisions.jsonl)与[切换索引](release-candidate/trace/trace-switches.json)按调度批次记录，不是逐 token 时间戳。

## 复现与限制

本地服务报告 `vllm-hust-vspec 0.15.2.post1`、`vllm 0.17.2rc1.dev5871+g762f85b31.empty`、`vllm_ascend 0.25.1rc2.dev0+hust.20260903.4.g4e57439e5.d20261111`。本地插件工作树基于 `ca9611d3f7494563069d7eda4330be2439f52da7`，但含[未提交的原生 MTP2/后端静态形状兼容修正](release-candidate/code/v0.15.2-local-compat.patch)，不能将五臂结果称作该公开 SHA 或 PyPI wheel 的原样复现。模型权重不随证据包再分发，且尚无旧路径与当前权重逐文件哈希一致性证明。
