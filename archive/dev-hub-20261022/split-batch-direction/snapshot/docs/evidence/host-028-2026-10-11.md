## 3. 版本串漂移警示（重要，勿依赖版本串语义）

镜像 hust 构建的 `vllm_ascend` 版本字符串停留在 `0.25.1rc2.dev` 窗口，**代码实际已追平
vllm 0.28 host**。本此门"零修改放行"含有构建管道恰好未改版本号的运气成分。结论：
**`host.version_range` 的满足不能推断宿主代码代际**——宿主升级核对必须照 §4 清单
（静态 seam_diff + 真机冒烟）执行，本次已执行且通过。

## 4. cascade 内核在 0.28 底座不可载（环境缺口，非插件缺陷）

- 现象：`import ascend_kernel` → `OSError: libascend_kernel.so: version GLIBC_2.38 not found`
- 原因：v2026.9.26/9.27 wheel 均按旧底座（glibc ≥2.38）构建；0.28 镜像底座 Ubuntu 22.04.5 = glibc 2.35
- 已验证非脏装：从官方 release 重下 wheel（sha256 `57472c4e…` 与钉版一致）装后复测，失败集不变
- 处置：**0.28 主栈暂不启用 cascade**（2026-10-11 用户裁定：新模型 + TP=2 负载下该算子无需加载）；
  重启用条件 = Ubuntu 22.04 底座重建 wheel（CANN 9.1.0 工具链在位）+ 重跑
  `tests/test_cascade_fail_open.py` + `tests/test_cascade_plugin.py`（5 个环境红灯转绿）
- 版本错位登记：pyproject `kernels` extra 钉 `ascend-kernel==2026.9.26`，
  算子仓（vllm-hust-cascade-kernel）已分发 v2026.9.27——两仓版本对齐在 cascade 重启用时一并处理
