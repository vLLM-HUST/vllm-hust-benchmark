# 数据集中治理

## 唯一归属

实验原始记录、配置、运行回执、测量汇总、配对关系、价格依据、数据修正及用于发布的派生数据 统一由 vllm-hust-benchmark 接收、审核和版本管理。网站负责展示，不作为实验数据源。

已有 benchmark 原文件必须复用，不因网站文件名或 JSON 排版不同而复制一套新权威数据。 `website-publication/data/`
的初始快照是网站公开字节的保全导入，不等于逐项来源验收。 来源审计固定到导入前的 benchmark 提交，排除新导入副本，避免循环证明。

## 清理顺序

1. 按已提交 Git 对象识别完全相同的文件，登记现存 benchmark 路径。
1. 对不相同文件检查 JSON 等价、生成脚本、归档成员和旧版本，不能直接判为数据缺失。
1. 对确实只保存在网站、MOD 仓库或服务器的原件，保留原始字节、校验和、采集来源和运行 ID， 迁入 benchmark 的对应实验目录；不重写原始证据。
1. 用固定 commit、源路径和校验和登记网站发布文件的生成关系。
1. 先验收 benchmark 归档与配对关系，再移除重复暂存副本及网站数据维护入口。

## 配对约束

每条性能曲线保留自身方案、模型 revision、运行版本、拓扑、工作负载、窗口和运行 ID。 不能把不同 MOD 或组合的最佳点拼成同一方案曲线。跨配置的逐指标最优值只能单独作为
明确标注的比较视图，不能冒充同工况配对实验。

## 后续门禁

- 数据 PR 只提交 benchmark；网站 PR 禁止发布数据和证据文件变更。
- 网站构建只消费 benchmark 中已经合并的固定版本。
- 生成物必须有来源映射及内容校验；未登记文件、源版本不匹配、手改生成物均使检查失败。
- 原始数据修订新增版本并说明原因，不覆盖已被报告引用的原件。
- 发布检查和数据 PR 检查必须作为仓库必需检查；不得仅凭本地通过宣称远端已强制执行。

## 当前状态

`source-audit.json` 是固定在迁移前两仓库提交的可复算清单。`needs-provenance-review` 表示需要继续追溯，
不是缺测判定。它也不代表裸机归档已核实或完整迁移已完成。 远端合并、发布流程接入和必需检查配置尚未完成。
